# 文渊 · 需求与决策

> 本文件是需求与设计决策的**唯一事实来源**。每次讨论有新结论就更新这里，不要散落在聊天记录中。
> 最近更新：2026-07-26

## 一、项目定位

**文渊** —— 中国古典文学阅读站。让人**进得来、读得下去、还能细品**。

三个不能丢的目标，按优先级：

1. **吸引** —— 首屏就抓住路人，不是一上来给一张目录表
2. **不晦涩** —— 原文有译文，生僻字有注音，难懂处有注释，且不打断阅读节奏
3. **可细品** —— 想深入的人能读到背景、思想、赏析

## 二、核心机制：三层阅读深度

同一篇作品，三种进入方式，用户自选沉浸程度。

| 层 | 名称 | 内容 | 面向 |
|---|---|---|---|
| L1 | 一眼 | 名句 + 意境图 + 一句人话解读 | 路人，零门槛 |
| L2 | 通读 | 原文 / 白话译文（原文、对照两种模式）+ 生僻字注音 | 读得下去 |
| L3 | 深读 | 逐句注释、典故、创作背景、作者小传、赏析、思想脉络 | 细品 |

**关键约束：注释默认隐藏，点击词句才浮出（渐进披露）。** 这是"不晦涩但也不打断"的核心机制 —— 注释常驻会把正文切碎，全藏起来又等于没有。

## 三、内容板块

| 板块 | 范围 |
|---|---|
| 诗词 | 诗经 / 楚辞 / 唐诗 / 宋词 / 元曲 |
| 文章 | 古文观止路线：岳阳楼记、滕王阁序、前赤壁赋、出师表… |
| 典籍 | 道德经 / 论语 / 庄子 / 孙子兵法 / 世说新语（章节体，需全书导读 + 章节脉络） |
| 人物 | 作者生平、交游关系、人生轨迹 —— 已落地，见十二之五 |
| 长河 | 时间轴，看文学流变 —— 已落地，见十二之六 |
| 地图 | 长安 / 洛阳 / 江南 / 塞北，地理维度读诗 |

## 四、入口设计（首页做钩子，不做目录）

- **每日一句** —— 配图横幅打底，名句压在画面留白上
- **顶栏板块** —— 诗词 / 文章 / 典籍 就地筛选卷首精选，不跳页；空板块与未开工的栏目（人物 / 长河 / 地图）置灰。阅读页顶栏与面包屑用 `home.html?sec=<板块>` 跳回来
- **心境选读** —— 孤独 / 壮志 / 闲适 / 离别 / 思乡 / 释然
- **时空长河** —— 各朝代作品量条形图，可点击进入
- **卷首精选** —— 跨体裁卡片，悬停浮现配图
- 待做：诗人星图（李白—杜甫—高适交游网络）、诗词地图

板块、长河、心境三个筛选器**互斥**：同时亮着两个，读者搞不清眼前这几张卡片是按什么筛出来的。

## 五、视觉方案

### 已定：A2「宣纸素卷 · 紧凑版」

评审过 4 个方案后确定：

| 方案 | 结论 |
|---|---|
| A 宣纸素卷 | 调性对，但**垂直方向撑太开、横向没用起来**，小屏幕上大片空白 → 改造为 A2 |
| B 墨色夜读 | 氛围强但长文阅读累 → 暂不用 |
| C 线装竖排 | 最有仪式感，但**竖排阅读习惯成本高，很多人不愿用** → 降级为未来的可选「古籍模式」开关 |
| D 新东方极简 | 干净但古意淡 → 不用 |

**A2 相对 A 的修正**：留白保留但收紧，横向空间用栅格吃满。首屏改为配图横幅（解决"页面最上方空"）；首页用「精选卡片 + 侧栏」两栏；阅读页用「阅读深度 + 作品信息 / 正文 / 名句 + 注释一览」三栏 —— 三层深度是核心机制，放左栏顶端，窄屏收掉右栏时它也还在。

## 六、配图

每篇作品配一组图，AI 生成。

| 用途 | 规格 | 位置 |
|---|---|---|
| `hero` | 2.35:1 | 首页横幅、阅读页页首横幅 |
| `cover` | 4:3 | 卡片封面（悬停浮现） |
| `scene[]` | 16:9 | 长文与典籍的分章插图（可选） |

三条硬约束：

1. **统一风格锚** —— 所有图共用一段 style prompt，按朝代微调：唐诗→青绿山水；宋词→水墨淡设色；先秦典籍→简牍拓片；文章→白描
2. **主体固定在右三分之一，左三分之二留白** —— 站点的标题与名句压在图片左侧，方向不能让模型自选（详见十二之三）
3. **不画人脸特写** —— 只出意境，避开恐怖谷与历史人物形象争议

**prompt 由读过原文的模型产出**（解析阶段顺手写 `imagePrompt` 字段），这是质量关键 —— 不能用模板套。

出图模型：**FLUX.2-pro**（经 `baoyu-image-gen` skill，Azure 端点）。已验证效果符合预期。

## 七、导入流水线

用户丢进一份原文 → 自动产出结构化 JSON → 前端直接读。

```
data/raw/道德经.txt
      ↓
[1] 切分 Segment    规则切分，不用 AI —— 按章/篇/阕/句拆
      ↓
[2] 识别 Identify   AI：书名、作者、朝代、体裁、一句话钩子
      ↓
[3] 逐章解析 Annotate  AI 分批：白话译文 / 逐句注释 / 典故 / 注音 /
      ↓                难度分级 / 名句标记 / imagePrompt
[4] 全书导读 Overview  AI：成书背景、思想脉络、章节地图、推荐阅读路线
      ↓
[5] 出图 + 压缩       FLUX.2-pro → webp
      ↓
[6] Zod 校验 → 失败把错误回灌给模型，同轮自修复
      ↓
data/works/dao-de-jing.json
```

**设计要点**

- **切分不交给 AI** —— AI 干切分又慢又会漏字。正则切完再喂给 AI 逐块解析。
- **每章存 content hash** —— 重跑只补新增/改动的章节，不重复烧 token。
- **AI 只能通过 `emit_work` 工具交付** —— 不解析自由文本 JSON。（沿用 knowledge-atlas 的成熟做法）
- **注释挂在「句」上并带 `term` 字段** —— 前端在原文里做子串定位加高亮，这是「点词出注」的数据基础。

## 八、数据结构

```ts
Work {
  id, title, type: 'poem'|'ci'|'essay'|'classic', dynasty,
  author: { name, bio, era },
  hook: string,                    // L1：一句人话
  famousLines: [{ text, translation }],
  overview: {                      // L3：全书导读
    background, coreIdea, structure,
    readingPath: string[],         // 「先读第 1、8、33 章」
    difficulty: 1..5
  },
  media: { hero, cover, scenes[] },
  chapters: Chapter[]              // 诗词就是单章
}

Chapter { index, title, lines: Line[], translation, commentary, difficulty }
Line    { text, translation, notes: Note[] }
Note    { term, pinyin?, explain, type: 'word'|'allusion'|'person'|'place' }
```

一份 schema 同时喂三层阅读：`hook`→L1，`translation`→L2，`notes`/`overview`/`commentary`→L3。

## 九、技术选型

| 层 | 选型 | 理由 |
|---|---|---|
| 站点 | 纯静态（无后端、无数据库） | **不需要用户系统、笔记、收藏** |
| 前端 | Vite + React + TS，读本地 JSON | 可白嫖 GitHub Pages |
| 内容管线 | Node + TS + `@github/copilot-sdk` | 已登录，无需额外 API Key |
| 校验 | Zod | 与 knowledge-atlas 一致 |
| 出图 | FLUX.2-pro（baoyu-image-gen skill） | 水墨肌理质感好 |
| 图片压缩 | sharp → webp，q78 | 552KB → 94KB（-83%） |
| 部署 | GitHub Pages + Actions | 见下 |

**明确不做**：用户系统、笔记、收藏、阅读进度记录。

## 十、部署

- 仓库：`cubika/wenyuan`
- 分支 `main` push 后由 `.github/workflows/pages.yml` 自动构建部署
- 当前上传 `prototypes/`；接入 Vite 后改为 `npm run build` + 上传 `dist/`

## 十一、工作约定

- `png` 是出图中间产物，**不进版本库**；只提交压缩后的 `webp`（见 `.gitignore`）
- 生成的图片**不读入 AI 对话上下文**，只报路径和体积
- 原型页面**一页一职责**：`home.html` 是首页，`work.html` 是阅读页，不要把两者塞进同一个滚动页
- `data/works/*.json` 是流水线产物，**进版本库**（重跑要花 token，不能让 CI 每次重生成）
- `prototypes/data/` 由 `scripts/build-data.mjs` 生成，**不进版本库**
- **直接提交 `main`，不走 PR**。每轮改动经确认后即推送，Actions 自动部署。推送前必须跑通 `npm run check` 与 `node scripts/verify-ui.mjs`。

## 十二、已落地（2026-07-26）

流水线与站点已端到端跑通：

- `packages/schema` —— Zod 契约 + 两项跨字段校验（注释锚点、名句出处），7 项单测
- `packages/pipeline` —— 切分 / 识别 / 译注 / 导读 / 出图 五段，emit 工具交付 + 校验回灌自修复，7 项切分单测
- 已导入 6 篇覆盖四种体裁：《春江花月夜》《蒹葭》(poem)、《江城子·记梦》(ci)、《爱莲说》《陋室铭》(essay)、《孙子兵法》十三篇 (classic)
- 站点改为数据驱动：`work.html?id=<id>` 读 JSON 渲染，注释按 `term` 自动挂回原文
- **排版按体裁分流**：诗词逐句成行，文章/典籍按段连排（详见下节）
- **顶栏板块接上行为**：诗词/文章/典籍 可点筛选，空板块置灰，`?sec=` 深链可回；人物是独立页面
- **人物板块**：5 位作者立档，列表页 + 详情页（生平年表 / 交游 / 代表作），作品页作者名可点进人物页
- **长河板块**：十二段朝代导语 + 按朝代分段的作品与人物，空朝代留灰照实呈现
- **侧栏限高自滚**：短文（陋室铭 99 字 / 19 条注释）的侧栏比正文长得多，既会把整页撑出大片空白，sticky 高过视口时底部注释还根本滚不到。左右两栏都限高自滚，但**藏掉滚动条**（页面上两条滚动条很碍眼），改用底部渐隐提示，滚到底自动撤掉
- **阅读深度移到左栏顶端**：它是全站核心机制，不该缩在右栏最下面；右栏在 ≤1180px 会整列收掉，放右边等于窄屏上直接消失
- 96 项 UI 断言全绿

**实测有效的质量闸门**（都拦下过真实错误）：

| 闸门 | 拦截对象 |
|---|---|
| 逐句比对原文 | 模型「顺手」改标点、换异体字、合并句子 |
| `term` 子串校验 | 注释词条写成原文里没有的近义词，前端锚不上 |
| 名句出处校验 | 模型凭印象写了别篇的名句 |
| 句数一一对应 | 模型漏译或多译 |

## 十二之二、文章排版（2026-07-26）

散文的单位是**段**，不是句。诗词逐行的排法套到文章上，会把一篇散文排成分行诗。

| | 诗词（poem / ci） | 文章 / 典籍（essay / classic） |
|---|---|---|
| 原文 | 一句一行，换行即作者的断句 | 句子在段内连排，首行缩进两格 |
| 对照 | 逐句译文贴在句下 | **段级译文**：整段读着才连贯，逐句对照会把文气切碎 |
| 定位 | 行即单位 | 句级悬停加极淡底衬，防止连排后串行 |

实现要点：

- **段落信息在切分阶段就得留住**。`segment` 按「连续非空行为一段」算出段号，写进 `Line.para`；一旦在这一步丢掉，后面谁也补不回来。
- **段号由规则算，不问模型**。`applyParas` 一律覆盖模型返回值 —— 段落是排版信息，不是理解结果。
- **段号不进 content hash**。改分段不该让整篇译注缓存落空、白烧一遍 token。

## 十二之三、配图构图（2026-07-26）

首页横幅与阅读页页首的**文字固定压在图片左侧**（左起渐变遮罩），所以：

> **主体必须在右三分之一，左三分之二留白。** 这个方向不能让模型自选。

早期 prompt 只要求「主体压在一侧」，模型有一半概率选左边，出来的图主体正好被标题盖死（《爱莲说》《陋室铭》《蒹葭》都中过）。约束已写死在 `stages/overview.ts`；`jianjia` 的图是旧约束下的产物，待重出。

## 十二之四、典籍多章阅读（2026-07-26）

《孙子兵法》十三篇跑通了章节体。要点：

- **整本平铺，不做翻页**。十三篇一页读到底，左栏目录随正文高亮（IntersectionObserver），点目录跳章。分页会把「通读一本书」切成十三次点击。
- **大意与赏析挂在各章下面**，不是全书攒成一坨 —— 读完一章就该能就地深入；全书细读只留背景 / 核心 / 结构 / 手法 / 影响 / 阅读路线 / 作者。
- **侧栏注释按章给**。全书 552 条平铺在侧栏里翻不动，也没人会为查一个词从头滚到尾；跟着当前章换。
- **章题以原文为准**。模型逐章独立作业，让它「整理」标题会得到十三种格式（`始计第一：…`、`作战第二（作战篇）`、`《孙子兵法·军形第四》`）。原文自带篇名就用原文，没有篇名才让模型拟。
- 切分新增「篇名第 N」式篇题识别（`始计第一`），并剥掉 markdown 的 `#` 记号。

**长典籍实测**：13 篇 7447 字，逐章译注约 9 分钟、552 条注释；重跑时全部命中缓存，只重算导读。

## 十二之五、人物板块（2026-07-26）

人物是**独立实体**，不是作品的附属字段。作品里的 `author.bio` 是围着那一篇写的（「此诗把江潮…」），换到人物页就成了偏题的小传，所以人物单独立档：`data/people/<id>.json`。

数据结构：一句话定位 / 别称 / 生卒 / 小传 / 关键词 / **生平年表** / **交游** / 代表作 / 人物意境图。

**硬校验**（都拦下过真实错误）：

| 闸门 | 拦截对象 |
|---|---|
| 年表升序 | 模型把「早年」「晚年」的条目排乱 |
| 年表落在生卒区间内 | 把追赠、身后评价当成生平事件写进年表 |
| 生年不晚于卒年 | 生卒填反 |
| `workId` 必须是站内已有作品 | 代表作凭印象挂一个不存在的链接 |
| 年表至少 3 条 | 只写「生」和「卒」等于没有年表 |

**设计要点**

- **姓名是人物的自然主键，id 以已有档案为准**。模型每次挑的 id 都不一样，漂了就链接失效、配图丢失。
- **名下作品由 works 反查**，不信 `masterpieces.workId`。站内收录了什么是事实，模型漏填不该让作品从人物页消失。
- **人物配图不画人像**。只出与这个人强绑定的意象、器物、场景（苏轼→赤壁夜游的江岸与酒器）。
- **人物列表按时间排**，生卒不详的按朝代落位 —— 否则孙武会排到苏轼后面。
- **朝代写法在同步阶段统一**（「唐代」→「唐」）。`data/` 保持模型原样，`prototypes/data/` 是派生产物，归一化放在那一步。

## 十二之六、长河（2026-07-26）

**按朝代等宽分段，不按公元年线性排。** 站内跨度两千多年，真按年份画，先秦一个点之后就是一千多年空白。十二段等宽，段内才是内容多少。

**空朝代不藏**。秦、汉、魏晋…没收录的段照样出现，导语照写，只压暗。它同时是「这个站还缺什么」的进度条。

### 导语怎么保证不过期

这是这一版最要紧的设计。朝代导语想跟站内作品挂钩，但作品会不断增加 —— 挂了钩就得跟着重写。解法是把两件事拆开：

| 层 | 内容 | 谁产出 | 加新作品会怎样 |
|---|---|---|---|
| 这个时期文学在变什么 | 「诗从宫廷走到边塞与市井，格律定型，题材反而放开」 | AI 一次生成，入库 | **一个字都不用改** |
| 这个朝代站内有什么 | 作品卡、人物卡 | `build-data` 从 works / people 反查 | **自动出现** |

与人物页「名下作品由 works 反查，不信 `masterpieces.workId`」是同一条原则：**「站内有什么」是事实，永远反查，绝不写进 AI 文本。**

不靠嘱咐，靠闸门：

| 闸门 | 拦截对象 |
|---|---|
| 导语不许出现书名号 | 点名具体作品，加一篇就过期一次 |
| 导语不许点名站内作者 | 读者会读成「站内推荐」；站外人物（李白、杜甫）不受限，他们只是历史背景 |
| 十二段 id / name / 顺序固定 | 模型改名、漏段、乱序 |
| 起讫年成立且逐段递增 | 年代填反 |

**十二段一次交付**，不是逐段生成 —— 长河讲的是「变」，每段得知道上一段什么样才说得清变在哪里。逐段独立作业只会得到十二段各说各话。

**朝代归并口径只有一份**，算在 `build-data` 里写进索引（`eraId` / `eraName` / `eraStart`），首页长河与长河页共用。之前前端与断言各写一份归并规则，必然会漂。
